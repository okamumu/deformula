# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

`deformula` is a CRAN R package implementing double exponential (Takahasi–Mori) quadrature for
one-dimensional integrals. Two transformations are provided: `tanh_sinh` for a finite interval
and `exp_sinh` for `[0, Inf)`. The numerics live in C++ (header-only templates) and are exposed
to R through Rcpp.

## Commands

The host does not need R installed. `Dockerfile` pins `rocker/r-ver` and the `Makefile`
wraps `docker run` (mapping your uid so generated files are not left owned by root):

```sh
make image      # build the image; only needed once, or after editing the Dockerfile
make document   # roxygen2::roxygenise() -- regenerate NAMESPACE and man/
make test       # devtools::test()
make check      # R CMD build + R CMD check --as-cran
make readme     # devtools::build_readme()
make shell      # interactive shell in the container
make clean      # remove deformula.Rcheck/, tarballs, src/*.o, src/*.so
```

The image installs TinyTeX and `tidy`, and strips Ubuntu's hardening flags from R's
`Makeconf`, so `make check` reports the same findings a CRAN machine would rather than
artifacts of the container.

Equivalent commands if you do have R locally, from the package root:

```sh
R -q -e 'Rcpp::compileAttributes(); devtools::document()'   # after changing // [[Rcpp::export]] or roxygen
R -q -e 'devtools::load_all()'                              # compile + load for interactive work
R -q -e 'devtools::test()'                                  # full test suite
R -q -e 'devtools::test(filter = "zeroinf")'                # one test file (tests/testthat/test-zeroinf.R)
R -q -e 'devtools::check()'                                 # R CMD check, as CI runs it
R -q -e 'devtools::build_readme()'                          # README.md is generated from README.Rmd — never edit README.md
```

`make win` / `make mac` submit the tarball to win-builder (r-devel) and the macOS builder
before a CRAN release; both mail their results to the Maintainer address in `DESCRIPTION`
rather than printing anything useful.

`make submit` opens an interactive R session in the package; type
`devtools::submit_cran()` there to upload the tarball with `cran-comments.md` as the
submission comment. It deliberately does not run the call for you: `submit_cran()` confirms
through `utils::menu()`, which reads the terminal, and there is no way to preload the call —
`R -e` feeds the expression through stdin so `menu()` has nothing left to read,
`R --interactive -e` ignores the expression entirely, and `.Rprofile` / `.First` run before
`utils` is attached, which `submit_cran()` needs. CRAN then mails a confirmation link that a
human has to click.

CI (`.github/workflows`) does not use the Docker image; it installs R directly via
`r-lib/actions`. `R-CMD-check` runs a five-way matrix — ubuntu r-devel / r-release /
r-oldrel-1, macOS, Windows — and `test-coverage` reports to codecov. **The r-devel job
exists on purpose**: the package was archived from CRAN over a note that only r-devel
reported, back when this workflow was release-only and nothing surfaced it.

## Architecture

The whole numerical core is in `src/deformula.h` as an abstract base class `deformula::Deformula`
plus two subclasses that differ only in the change of variable:

- `DeformulaZeroToInf` — `phi`/`phidash` for `exp_sinh` on `[0, Inf)`
- `DeformulaMinusOneToOne` — `phi`/`phidash` for `tanh_sinh` on `(-1, 1)`; the R wrapper rescales
  to `(lower, upper)` by an affine map, scaling `x`, `w` and `value` accordingly.

`getWeight()` is the driver: it evaluates the trapezoid sum at step `h`, then repeatedly halves `h`
(doubling the abscissa count) until the relative change is under `reltol` or `maxiter` is reached.
Nodes are kept as `DeformulaElement{t, x, w}` in `m_data` and sorted by `x`. Integrand values whose
magnitude falls below `zero` are truncated — the comparison is on `std::abs(w)`, since comparing
the signed value discards every negative contribution.

`m_info` is the contract with R: `0` = OK, `1` = max iterations reached, `2` = non-finite value.
`R/deformula.R:deformula.message()` maps that integer to the `message` string in the returned
list — **if you add an info code in C++ you must add the matching `switch` branch, or the R side
calls `stop()`.** NaN weights are *not* an error: at the ends of the exp_sinh transform `phidash`
overflows to `Inf` while the integrand has underflowed to `0`, so `Inf * 0 = NaN` is expected and
those nodes are dropped silently.

Layering: `R/deformula.R` (user-facing `deformula.zeroinf`, `deformula.moneone`) →
`R/RcppExports.R` / `src/RcppExports.cpp` (both generated by `Rcpp::compileAttributes()`, never
edit by hand) → `src/deformula.cpp` (thin `List` marshalling) → `src/deformula.h` (algorithm).

Both exported functions return a list of `value`, `x`, `w`, `t`, `h`, `message` — the node/weight
vectors are part of the public API, so tests and downstream code may rely on them.

## Conventions

- roxygen2 with markdown; `man/*.Rd` and `NAMESPACE` are generated — edit the roxygen blocks.
- testthat edition 3; tests assert integrals against closed-form values with `expect_equal`.
- Do **not** reintroduce `SystemRequirements: C++11` or `// [[Rcpp::plugins("cpp11")]]` — that
  is what got the package archived from CRAN on 2026-02-15.
- Keep R and Rd sources ASCII-only; CRAN flags non-ASCII in `man/*.Rd`.
- `src/deformula.h` can be exercised without R: compile it against a small shim providing
  `Rcpp::wrap`/`Rcpp::as` and drive it with `std::function` integrands.
